## Inci's Modifications to the Bunch Compression Benchmarking Code for the Spallation Neutron Source (SNS) at Oak Ridge National Laboratory (in PyORBIT) ##
- The dated folders contain experimental data from 2025-01-26 and 2025-02-16 beam studies, as well as the subsequent plotting and analysis tools developed by Austin Hoover.
- The folder labelled "plotting_scripts" contains the simulation benchmarking scripts I've written using this experimental data: simplotsnosc.py (without Longitudinal Space Charge), simplotslongsc.py (with Longitudinal Space Charge), rmswidthplots.py (RMS width v. Number of Turns comparison for simulation v. experiment). 
- An optimization script to find the optimized energy spread required for the simulation beams to match the experimental Probability Density v. z width has been implemented as optsimplotslongsc.py.
- The relevant output folders are scsimsout (with Longitudinal Space Charge), simout (without Longitudinal Space Charge), rmswidths (RMS Width v. Number of Turns plots), phasespaceplots (Phase Space Plots that are from the Simulation only). The first three folders include exp_changes, which are more or less the final plots that went into the poster and the paper. The changes implemented for them are as follows:
  1) We realized that we haven’t modeled the ramping of the injected bunch length. (“zlim” in the script) The bunch length is actually shorter in the first few turns and then ramps to its maximum value later on. The ramp time is ~100 turns, so the injection takes about that time longer for the experiments simulated. This can be noted in the run.sh commands file, as injection for 300 turns is implemented as injection for 400 turns. This is explicitly written in the name of the rmswidth plots with rms400_ , but the rest it's indicated as rampedfig_ plots.
  2) The number of accumulated turns in our experiments is 100 more than requested from the diagnostics screen. For example, in Exp02/Case01, it looks like we actually injected 200 turns, not 100 turns.
  3) The initial measured profiles in the old/ folder had some negative values that were not removed; Austin later subtracted the minimum from each profile to remove the vertical offsets (`values = values  - values.min()`).
